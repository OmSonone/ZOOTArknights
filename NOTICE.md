# NOTICE — provenance and attribution

ZOOT (Zeroth Order Oil Tank) is a local-first Arknights planner. It is unaffiliated with
Hypergryph, Studio
Montagne, Yostar or the Krooster project.

A significant part of its game knowledge and a few algorithms were **copied or ported
from [ak-roster (Krooster)](https://github.com/neeia/ak-roster)**, which is released
under the **BSD Zero Clause License (0BSD)**. This file records exactly what came from
where so the provenance stays clear.

## What was copied / ported from ak-roster

| Area | ak-roster source | What ZOOT uses | ZOOT path |
| --- | --- | --- | --- |
| Game data | `src/data/operators.json`, `items.json`, `skins.json`, `factions.json` | Copied verbatim. These files are generated by ak-roster from the two game-data repositories below. | `public/data/*.json` |
| Level / LMD / EXP tables | `src/util/changeOperator.ts` (`MAX_LEVEL_BY_RARITY`, `COST_BY_RARITY`, `MAX_PROMOTION_BY_RARITY`, `MAX_SKILL_LEVEL_BY_PROMOTION`, `MODULE_REQ_BY_RARITY`) | Copied verbatim. | `src/lib/costTables.ts` |
| Operator edit rules | `src/util/changeOperator.ts` (`defaultOperatorObject`, `changeOwned`, `changePromotion`, `changeLevel`, `changeSkillLevel`, `changeMastery`, `changeModule`, `changeSkin`, `clamp`) | Ported with typed `OperatorData` arguments; same clamping and gating semantics. | `src/lib/operator.ts` |
| Level-cost calculation | `src/pages/tools/level.tsx` (`levelingCost`) | Ported; same per-level tables and slicing. | `src/lib/planner.ts` |
| Goal expansion semantics | `src/types/goalData.ts` (`GoalData`, `getPlannerGoals`) and `src/components/planner/goals/PlannerGoalAdd.tsx` | Reimplemented as a single target-state goal (`PlannerGoal`) that expands into the same per-promotion / per-skill / per-module rows. | `src/lib/types.ts`, `src/lib/planner.ts` |
| Material aggregation | `src/util/fns/planner/getGoalIngredients.ts`, `combineGoals.ts` | Adapted into `goalView` tasks + `buildMaterialPlan`. | `src/lib/planner.ts` |
| Crafting expansion | `src/util/fns/depot/canCompleteByCrafting.ts`, `itemUtils.ts` | Adapted. Chips are treated as farmable leaves because the chip recipe graph is cyclic. | `src/lib/planner.ts` |
| EXP → battle records | `src/util/fns/depot/expToBattleRecords.ts`, `depotToExp.ts` | Same greedy conversion approach. | `src/lib/planner.ts` |
| Yostar login chain (EN/JP/KR) | `src/util/hgApi/yostarAuth.ts` | Ported to Node ESM with the same endpoints, headers, MD5 salt, HMAC-SHA1 key, device handling and step order. | `server/yostar.mjs` |
| Import field mapping | `src/components/app/GameImport.tsx` | Reimplemented against ZOOT's save model (chars/tmpl, equip modules, skills/masteries, training room, inventory, supports, potential tokens). | `src/lib/gameImport.ts` |
| Depot OCR approach | `src/util/fns/depot/getMaterialFromImage.ts` | Uses the same library (`@arkntools/depot-recognition`), moved server-side with a disk cache instead of a web worker. | `server/depotOcr.mjs` |
| Goal editor / calculations reference | `src/components/data/input/EditOperator.tsx` and `src/components/data/input/Select/*` | Used as the behavioural reference for promotion-dependent caps, per-skill masteries, module requirements and skin gating. | `src/pages/InputPage.tsx`, `src/components/planner/GoalEditor.tsx` |

## What is original to ZOOT

- The entire neumorphic UI, design tokens, layout, motion layer and bespoke components
  (`src/components/neu/*`, `src/styles/*`).
- The local React state store, save schema/versioning/migration and JSON export/import
  (`src/state/store.tsx`, `src/lib/storage.ts`).
- The target-state goal model adaptation and its task expansion (`goalView`,
  `buildMaterialPlan`), including the no-double-count promotion LMD handling.
- The local import API, Vite middleware mounting, production server and browser-side
  import flow (`server/*`, `src/pages/ImportPage.tsx`).
- Roster, Collection, Profile and planner presentation.

## Not ported from ak-roster

Supabase/account sync, login profiles, network lookup, recruitment calculator, gacha
rate-up calculator, presets, CN/Skland import (Yostar only), TW/Bilibili auth, and the
original MUI/Next.js application structure.

## Upstream game data

ak-roster generates the four JSON files from:

- [Kengxxiao/ArknightsGameData](https://github.com/Kengxxiao/ArknightsGameData)
- [ArknightsAssets/ArknightsGamedata](https://github.com/ArknightsAssets/ArknightsGamedata)

Refresh them with `npm run update-data`, which shallow-clones ak-roster and copies the
four files.

Operator/item art is hotlinked from Krooster's CDN
(`https://d3gqz3mx7fd4v.cloudfront.net/images`) at runtime. The art belongs to the
game's rights holders.

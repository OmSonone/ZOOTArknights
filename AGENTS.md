This file is the short path to being productive in this repo. Read it fully before changing code.

## What this project is

**ZOOT (Zeroth Order Oil Tank)** is a local-only Arknights roster / collection / material
planner with a neumorphic UI. The name is a nod to Closure's replacement for PRTS.

- React 19 + Vite + TypeScript (strict), `react-router-dom`.
- No backend service, no accounts, no telemetry. The save lives in `localStorage`.
- The only server code is a small local proxy for the optional game-account import
  (the game APIs block browser CORS) and depot screenshot OCR.
- Game data ships in `public/data/*.json` and is fetched once at runtime (generated by **ak-roster**).

## The planner model (most important)

A goal is a **target state**, not a single action (mirrors krooster's `GoalData`):

```ts
interface PlannerGoal {
  id: string; opId: string; order: number;
  elite?: number;                  // target promotion
  level?: number;                  // target level inside target promotion
  skillLevel?: number;             // 1..7
  masteries?: Record<string, number>; // skill index -> target mastery 1..3
  modules?: Record<string, number>;   // moduleId -> target stage 1..3
}
```

`goalView(goal, roster, data)` in `src/lib/planner.ts` expands it into `GoalTask[]`:

- **Elite tasks**: one per promotion crossed, with `eliteLevels[i-1].ingredients`
  (includes promotion LMD).
- **Level tasks**: one per promotion range. Intermediate promotions go from 1 to
  `maxLevel(rarity, e)`; the target promotion goes to `goal.level`. Level costs are
  computed **inside a single promotion** so promotion LMD is not double-counted.
- **Skill level**: needs levels `current+1..target`, i.e.
  `skillLevels.slice(currentSkill - 1, targetSkill - 1)`.
  **Do not change this slice** without re-running the reference comparison (see below).
- **Mastery**: one independent task per skill, levels `current..target-1` in
  `skillData[i].masteries` (i.e. `slice(current, target)`).
- **Module**: one independent task per module, stages `current..target-1`
  (`slice(current, target)`).

Requirements / warnings:

- Mastery requires final state **E2 + SL7**.
- Modules require final state **E2 + `MODULE_REQ_BY_RARITY[rarity]`** (4★ 40, 5★ 50, 6★ 60).
- Skill level > 4 requires **E1**.
- The editor disables impossible targets; `goalView` clamps legacy/imported goals and
  emits warnings instead of throwing.

`buildMaterialPlan` sums **only incomplete tasks**, expands workshop recipes when
enabled, subtracts depot stock, and reports raw/farm rows. Chips (`" Chip"`,
`"Dualchip"`) are deliberately **not** expanded: their recipe graph is cyclic in the
game data. `totalLmd` is the expanded total (includes crafting fees).

Key invariants verified against ak-roster on 2026-10-28:

- 8,757 skill-level ranges (every operator with skills, every current/target pair) matched
  the reference `sum(skillLevels[L-2]) for L=current+1..target`.
- 5,736 mastery ranges (every skill of every operator, every current/target pair) matched
  `sum(skillData[i].masteries[L-1]) for L=current+1..target`.
- 3,018 module ranges (every module of every operator, every stage transition) matched
  `sum(moduleData.stages[s-1]) for s=current+1..target`.
- 417 combined “all masteries M3 + all modules stage 3” goals matched the sum of the
  reference ingredients, confirming aggregation does not double count.
- `MAX_SKILL_LEVEL_BY_PROMOTION = [4,7,7]`, `MODULE_REQ_BY_RARITY = [0,99,99,99,40,50,60]`.
- Promotion/level totals: 41 per-promotion EXP/LMD checks plus 6 full-target scenarios
  (including mid-promotion starts) matched direct table arithmetic. Promotion LMD is
  counted exactly once, in the elite tasks.
- Reference totals (EXP / total LMD): 6★ E0L1→E2L90 = 1,111,400 / 1,334,796
  (1,124,796 leveling + 210,000 promotion); 5★ E0L1→E2L80 = 734,400 / 819,325;
  4★ E0L1→E2L70 = 484,000 / 482,003; 3★ E0L1→E1L55 = 115,400 / 104,040;
  6★ E1L30→E2L90 = 1,062,408 / 1,263,293; 5★ E2L1→E2L80 = 495,000 / 447,378.
- **Sanity is not modelled.** Promotion and level upgrades only cost EXP/LMD/materials,
  and the bundled `items.json` has no stage drop rates or sanity values (same as krooster).

If you touch these, reproduce the comparison (temporary Node script + esbuild bundle is
the fastest route) before committing.

## Save file

`localStorage` keys:

- `zoot.state.v1` — the whole app state. The old `arknights-adda.*` keys are migrated
  and removed on first load; keep that path working when touching storage.
- `zoot.theme` — `light` | `dark`.
- `zoot.import-token.v1` — optional saved Yostar token.

State shape (`src/lib/types.ts` → `AppState`):

```ts
{
  version: 1,
  roster: Record<opId, { op_id, favorite, potential, elite, level, skill_level,
                         masteries: number[], modules: Record<moduleId, number>, skin }>,
  goals: PlannerGoal[],
  depot: Record<itemId, number>,     // includes "4001" LMD
  profile: { name, uid, server, level, onboard, assistant, supports },
  plannerSettings: { includeCrafting, ignoreLmd, showBattleRecords }
}
```

Rules:

- Roster entries with `potential === 0` mean **unowned**; `defaultOperatorObject`
  produces the unowned shape (`elite: -1`, `level: 0`, masteries/modules `-1`).
- `masteries` are indexed by `operator.skillData` order; `modules` are keyed by module id.
- `normalizeState` must stay backward compatible. Legacy per-category goals
  (`kind: "elite" | "level" | ...`) are migrated to target-state goals. Mastery keys are
  numeric strings and validated with `/^\d+$/` — a past bug (`/^d+$/`) silently dropped
  masteries on reload.
- If you add a field: update `types.ts`, `createDefaultState`, `normalizeState`,
  the reducer action(s), and export/import. Bump `SAVE_VERSION` only for breaking changes.

## Import stack

- `server/yostar.mjs` — Yostar EN/JP/KR login chain:
  `yostar/send-code → yostar/get-auth → user/login → u8/user/v1/getToken →
   account/login → account/syncData`.
  Signing constants, headers and endpoints are ported from ak-roster.
- `server/api.mjs` — `/api/import/{mail,data,depot,health}`; mounted by
  `vite.config.ts` in dev/preview and by `server/serve.mjs` for `npm start`.
- `server/depotOcr.mjs` — @arkntools/depot-recognition, server-side; resources cached in
  `server/.cache` (gitignored, downloaded on first use).
- `src/lib/gameImport.ts` — API client, token storage, mapping from the game account
  into roster/depot/profile/supports (including Amiya's `tmpl` forms and the Training
  Room mastery bonus).

Security rules:

- Never log or echo emails, codes, tokens, or the Skland-style credentials.
- The server binds `127.0.0.1`; do not expose it by default.
- Only contact the official Yostar/game hosts used in `server/yostar.mjs`.
- Do not send credentials through third-party proxies.

Testing import without credentials: intercept `/api/import/mail` and
`/api/import/data` in a browser test and respond with a fixture `{ user, tokenData }`;
the whole UI flow and mapping can be exercised. Do not send real emails while testing.

## UI / design system

- Design tokens in `src/styles/tokens.css` (light/dark via `[data-theme]`).
- Neumorphic primitives in `src/styles/neu.css` + `src/components/neu/*`.
  Cards use raised shadows; inputs use inset shadows; never mix surfaces.
- Use the shared components (`Button`, `Chip`, `Segmented`, `Stepper`, `Switch`,
  `Select`, `Dialog`, `Stat`, `SearchInput`, `Icon`) instead of raw elements.
- **No native `<select>`** — use `Select` (searchable, keyboard, mobile bottom sheet).
- New pages: add route in `src/App.tsx` (lazy), nav entry in
  `src/components/layout/Shell.tsx`, use `Page` for the top bar, and follow the
  responsive rules (works at 320px; bottom nav ≤ 860px).
- Motion is centralised in `src/styles/motion.css`; respect `prefers-reduced-motion`.
- Images are hotlinked from krooster's CloudFront via `src/lib/images.ts`; always render
  through `Img` so failures fall back to a placeholder.
- `Stepper` uses an internal value ref so rapid clicks / long-press accumulate —
  keep that behaviour if you refactor it.

## Verification checklist

```bash
npm run typecheck
npm run build
npm run dev    # or npm start after build
```

Manual checks worth repeating:

1. Roster renders 434 cards; filters/search work; `/` focuses search.
2. Input: E0→E1→E2 caps 50/80/90 for 6★; changing promotion clamps level/skill;
   masteries are independent per skill; 3★ hides masteries; E2 skins disable below E2.
3. Planner: create E0L1→E2L90 goal; tasks include both promotions, three level ranges,
   SL1→7, per-skill mastery rows, module stages; total LMD/EXP match the numbers above.
4. Edit the goal; targets restore (including each mastery) after a page reload.
5. Materials: toggles, depot subtraction, craft expansion (no chips), copy list.
6. Import page: steps, cooldown, saved credentials, OCR upload/apply (mock the API
   endpoints for the account flow; OCR can run on a real depot screenshot).
7. Both themes, 320/390/768/1440 px; no horizontal overflow; no console errors.
